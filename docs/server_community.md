# Общее серверное сообщество — 29.10.2026

## Результат этапа

При заданном адресе API приложение читает общую серверную ленту и отправляет
публикации на сервер. Подключены фото, мастер-классы, поиск, свои работы и
счётчики, лайки, создание/редактирование/удаление комментариев, удаление своих
работ, прогресс читателей. Два клиента используют разные локальные базы,
но видят одну опубликованную работу и обсуждение на общем API.

На сервере хранятся также последнее открытое действие мастер-класса, выполненные
шаги и отметки материалов/инструментов. Они привязаны к серверному аккаунту и
восстанавливаются на другом клиенте. Сохранение рецепта в палитру и добавление
мастер-класса как проекта создают личные копии на устройстве читателя.
Синхронизация всей личной палитры, проектов и встроенных уроков этим не реализована.

Без адреса API продолжает работать прежний локальный режим. При ошибке сервера
показывается ошибка: публикация не записывается незаметно в местную ленту.
Ожидающие публикации не являются полноценной оффлайн-очередью.

## Права, хранение и повторная отправка

- `backend/community.py` добавляет HTTP API к существующему серверу. Пароли,
  почта и секрет Resend остаются в прежней серверной части; новые почтовые
  ключи или сервисы для сообщества не требуются.
- Автор записи и владелец прогресса определяются из Bearer-сессии. Подстановка
  `userId` в JSON отклоняется. Чужие работы/комментарии изменить или удалить
  нельзя, отозванные сессии и заблокированные аккаунты не выполняют действия.
- У сервера и клиента разные числовые ID пользователей. Кнопки владельца
  используют вычисленное сервером `isOwn`, поэтому совпадение чисел не даёт
  прав на чужую запись. Личные проекты и палитра используют прежние локальные
  привязки аккаунта из `remoteAccounts`.
- С устройства передаётся самостоятельный снимок только выбранных публичных
  материалов. Частный проект остаётся на устройстве; его заметки и дедлайн
  не отправляются. Сервер проверяет текст, категорию, теги, фото, структуру
  шагов и рецепты заново; незаявленные поля снимка не сохраняются.
- Фото передаются в JSON как Base64, проверяются Pillow и сохраняются в SQLite.
  Сохраняются прежние ограничения: 1–10 фото, до 10 МБ на входное фото,
  допустимые форматы/пиксели, удаление EXIF/GPS. Фактический поток запроса
  ограничен 48 МБ до разбора JSON, в том числе без верного Content-Length.
- `communityRequests` хранит идентификатор отправки, хеш данных и результат.
  Повторный запрос с тем же ключом и данными возвращает прежнюю публикацию;
  другой набор данных с этим ключом отклоняется. Сохранение работы, фото и
  ключа атомарно. Ключ новой формы сохраняется в памяти до подтверждения
  результата: повторяйте отправку с теми же данными, сохранив форму открытой.
- Для существующей местной работы `localPostExports` сохраняет ключ и результат
  переноса в клиентской базе. Её повторная отправка защищена от дублирования
  также после перезапуска приложения. Местная копия не удаляется.
- Серверные комментарии сохраняют прежние проверки: 5–1000 символов, текст
  помимо эмодзи, до 5 новых комментариев в минуту, изменение своего до 30 минут.
  Лимит теперь общий для сессий одного серверного аккаунта.
- Удаление публикации удаляет фото, лайки, обсуждение, прогресс и запись
  повторной отправки. Удаление аккаунта оставляет заглушку с чужими комментариями,
  удаляя его публичные фото и содержимое мастер-класса. Прошедшие копирование
  рецепты в чужих палитрах остаются самостоятельными копиями.

Список API доступен на `/docs`. Лента отдаётся страницами до 100 работ, клиент
загружает страницы для текущего списка; полноценный бесконечный скролл ещё не
добавлен. Изменения других пользователей появляются по «Обновить ленту» или
при повторном открытии раздела, без push и постоянного WebSocket сообщества.

## Обновление на своём компьютере

Дополнительных зависимостей по сравнению с предыдущим этапом нет. Остановите
API и приложение, обновите исходники и перезапустите **оба процесса**. Сохраните
прежние `LEPKA_SERVER_DATA_DIR` и `LEPKA_DATA_DIR`: схема обновится при запуске,
аккаунты и данные не нужно создавать заново. Команды выполняются из корня
репозитория. Нужны отдельные терминалы PowerShell.

В терминале вашего уже настроенного сервера, где заданы его каталог данных и
почтовые переменные:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

В обычном терминале приложения оставьте его прежний каталог данных:

```powershell
$env:LEPKA_API_URL = "http://127.0.0.1:8000"
$env:LEPKA_ALLOW_LOCAL_API = "1"
.\.venv\Scripts\python.exe main.py --port 8550
```

В третьем терминале можно проверить **вторую независимую клиентскую базу**:

```powershell
$env:LEPKA_API_URL = "http://127.0.0.1:8000"
$env:LEPKA_ALLOW_LOCAL_API = "1"
$communityCheckDir = Join-Path $env:TEMP ("LepkaCommunityCheck-" + [guid]::NewGuid().ToString("N"))
$env:LEPKA_DATA_DIR = $communityCheckDir
.\.venv\Scripts\python.exe main.py --port 8551
```

Этот третий терминал использует новую отдельную папку для проверки. Существующая
база первого клиента остаётся прежней. Откройте `http://127.0.0.1:8550` и
`http://127.0.0.1:8551`. Войдите существующими подтверждёнными серверными аккаунтами.
Тот же аккаунт подходит для проверки переноса прогресса между клиентами; второй
аккаунт — для проверки чужих работ и личных отметок. В тестовом режиме Resend
создание аккаунта на другую почту может требовать подтверждённого домена отправителя;
проверка сообщества не обходит подтверждение почты.

1. Первым аккаунтом опубликуйте тестовую работу с фото или мастер-класс из
   проекта. Во втором клиенте нажмите «Обновить ленту»: работа должна появиться.
2. Другим аккаунтом поставьте лайк и оставьте комментарий. Кнопки удаления
   чужой работы быть не должно. Первый аккаунт после обновления увидит действия.
3. Откройте мастер-класс, отметьте материал и шаг. Тем же аккаунтом войдите в
   другой клиент: позиция и отметки должны восстановиться с сервера.
4. Сохраните рецепт и добавьте мастер-класс в проекты. Эти личные копии
   появятся на устройстве получателя; исходный частный проект автора недоступен.
5. Для прежних местных работ откройте профиль → «Публикации на этом устройстве»
   → «Отправить эту работу на сервер». Выбирается только работа текущей привязки
   серверного аккаунта. Старые записи без фото требуют новой публикации с фото.
   Записи другого старого локального аккаунта доступны в локальном режиме;
   автоматического переноса владения по совпадению email/числовых ID нет.
6. Остановите API и попробуйте обновить ленту: должна появиться сетевая ошибка.
   Перезапустите его с прежним каталогом. Для проверки удаления используйте
   только свою специально созданную тестовую работу.

## Проверки

**215 тестов, OK**: прежние 192 и 23 новых (13 HTTP API, 10 интеграционных).
Все базы временные, почтовые ключи не используются, реальные письма не отправлялись.
Полный набор прошёл также с `LEPKA_API_URL=https://example.invalid`; тесты не
обращаются к пользовательскому API. `pip check` и `git diff --check` прошли.

Проверены права и сессии, совпадение серверного и локального ID у разных людей,
фото, поиск и страницы ленты, лайки и серверные ограничения комментариев,
сохранность прогресса после перезапуска API и входа из новой базы клиента,
удаление, транзакции, дубли при повторных/одновременных запросах, потеря ответа,
ручной перенос прежней работы без удаления местной копии, отсутствие локального
резервного сохранения при ошибке сети, обработчики настоящих элементов Flet.

В настоящем Chromium запущены два отдельных процесса Flet с независимыми
клиентскими базами и один отдельный процесс API. Публикация подготовлена
через HTTP API как тестовый набор данных. Два аккаунта увидели её в своих
клиентах; читатель поставил лайк, отправил комментарий, отметил материал,
перешёл на следующий шаг и сохранил рецепт. Проверка SQLite подтвердила:
пост, лайк, комментарий и прогресс находятся в серверной базе, в обеих клиентских
таблицах `posts`/`workshopProgress` записей нет, рецепт находится только у читателя.
Ошибок JavaScript не обнаружено. Новая публикация из Flet отдельно проверена
через обработчики формы и настоящий HTTP-сервер.

## Оставшиеся требования

У пользователя сервер пока локальный. Публичное HTTPS-размещение этим этапом
не выполнено; для разных реальных устройств нужен доступный им один HTTPS API.
APK не пересобирался, Android и отдельное окно Windows не проверены.

Серверное сообщество уточняет пункты 35–40 старого аудита. Пункт 45 о полном
оффлайн-режиме/синхронизации всё ещё выполнен лишь частично: нет очереди
отложенных действий, конфликтов и синхронизации всех личных проектов/палитры.
Не реализованы модерация с причиной и журналом, push, автодополнение тегов,
связь с избранным уроком/моделью, полноценные конкурсы, 3D и другие ранее
отмеченные требования. ТЗ и историческая дата сдачи не изменялись.
