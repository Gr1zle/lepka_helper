# Публикация личного проекта и обмен рецептами — 29.10.2026

Дополнение: опубликованный проект теперь открывается отдельным мастер-классом,
как встроенный урок. Актуальная форма, прогресс и проверки описаны в
[workshops.md](workshops.md). Ниже сохранён отчёт первоначальной связки проектов
и палитры; его 170 тестов — результат до этого дополнения.

## Связь с ТЗ и планом

Продолжен этап сообщества по плану на 29 октября. Пункты 4.1.4.10 и 4.1.8 ТЗ
описывают публикацию готовой поделки с 1–10 фото этапов и результата. Теперь
доступен переход из личного проекта в такую публикацию. Карточка содержит
фото, название, автора, категорию, описание, выбранные этапы и рецепты;
поддерживает прежние лайки и комментарии. Работа доступна также в поиске.

Выбор смесей для проекта и копирование рецепта чужой работы в свою палитру —
дополнение по пожеланию пользователя. В ТЗ прямо указаны сохранённые смеси,
но эти две связи отдельно не описаны. ТЗ и прежняя дата сдачи не изменены.

Уточнение предыдущего аудита: пункт 26 теперь включает локальные публикации в
поиск вместе с уроками, но не стал полным поиском 3D-моделей и цветов с историей
и автодополнением. Пункты 35–38 дополнены публикацией из проекта. Это не означает
готовность серверного сообщества или всех требований к публикациям.

## Данные и права

- `projectMixtures` хранит копии рецептов личного проекта. Добавление читает
  только собственную палитру; чтение, добавление и удаление проверяют владельца
  проекта. До 10 смесей на проект, одинаковая копия повторно не добавляется.
- Рецепт проходит ту же проверку, что и при сохранении в «Мою палитру»:
  2–5 базовых цветов, пропорции, масса, соответствие HEX и граммов расчёту.
- В форме публикации описание вводится отдельно. Оно не берётся из личных
  заметок. Итоговое фото обязательно; дополнительные фото и рецепты выбираются
  явно. В публикацию попадают только выбранные изображения и подписи этапов.
- Первая фотография — выбранный результат. Остальные идут в порядке этапов
  проекта. В `posts.projectDetailsJson` сохраняются описания опубликованных
  этапов и полные рецепты без личных ID, дедлайна и заметок.
- Проверка владельца, чтение выбранных материалов и создание публикации с
  фотографиями проходят в одной транзакции. Подстановка ID чужого проекта,
  этапа, смеси или объекта другого своего проекта отклоняется.
- Публикация — самостоятельная копия. Изменение/удаление проекта или исходной
  смеси её не меняет. Копирование рецепта из живой публикации создаёт личную
  смесь получателя; повторное и одновременное нажатие не дублирует её.
- Удаление публикации делает её рецепты недоступными для нового копирования.
  Ранее сохранённые копии остаются у получателей. При удалении аккаунта
  удаляются его личные смеси проектов и публичное содержимое его работ;
  чужие комментарии остаются под прежней заглушкой.
- Обновление схемы добавляет таблицу и колонку без удаления старых записей.
  Обычные публикации без связи с проектом продолжают работать.

## Как проверить на своём компьютере

Обновите приложение, сохранив прежнюю папку данных, и перезапустите его обычной
командой из корня проекта. Настройки работающего сервера аккаунтов не меняются.
Для этого этапа новых зависимостей и перезапуска API не требуется.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py
```

1. Во вкладке «Цвета» сохраните смесь, например белый + чёрный 50/50 на 100 г.
2. Создайте тестовый проект с двумя этапами и фото. В карточке проекта нажмите
   «Добавить смесь из палитры» и выберите рецепт.
3. Нажмите «Опубликовать в сообщество». Выберите итоговое фото, отметьте второе
   фото и рецепт, заполните отдельное описание, сложность, время, материалы и
   инструменты. Сначала отмените форму:
   публикация не должна появиться. Откройте снова и опубликуйте.
4. На «Главной» и в «Поиске» найдите работу и нажмите «Открыть мастер-класс». Проверьте два фото, подписи,
   рецепт с процентами и граммами. Неотмеченные рецепты, заметки и дедлайн
   должны остаться личными. Новые мастер-классы поддерживают фильтры сложности
   и времени; флажок «Только с видео» должен быть выключен.
5. Войдите вторым аккаунтом **в эту же копию приложения с той же локальной
   базой**. Сохраните рецепт работы в свою палитру. На «Цветах» откройте его:
   должны появиться компоненты 50/50 по 50 г. Повторное сохранение не создаёт
   дубликат. Личный проект автора во вкладке «Проекты» не появляется.
6. Автором измените/удалите только тестовый личный проект: публикация должна
   сохраниться. Затем удалите тестовую публикацию с подтверждением: ранее
   сохранённый вторым аккаунтом рецепт должен остаться в его палитре.

## Проверки и ограничения

Полный набор: **170 тестов, OK**, включая 19 новых проверок сервисов SQLite и
настоящих элементов Flet. Использованы отдельные временные базы и синтетические
изображения. Проверены права, выбор материалов, границы 10 фото/10 смесей,
отсутствие личных данных в публикации, откат транзакции при сбое второго фото,
повторная инициализация, повреждённые записи без перезаписи, удаление проекта,
публикации и аккаунта, одновременное копирование, поиск и старые обработчики
после выхода. Установленный у пользователя адрес API не используется тестами:
полный набор проверен также с `LEPKA_API_URL=https://example.invalid`.

В настоящем Chromium при 390 × 844 выполнен сценарий двух аккаунтов:
выбор смеси из палитры → публикация двух выбранных фото и рецепта → вход второго
аккаунта в отдельном браузерном контексте → сохранение рецепта → открытие его
в Color Mixer. Временная SQLite подтвердила два фото, отсутствие личных заметок
в публикации и рецепт получателя 50/50 по 50 г. При проверке формы обнаружено и
исправлено отсутствие немедленного отображения отметок выбора фото/смесей:
обработчик изменения обновляет страницу. После исправления полный набор
из 170 тестов выполнен повторно. `pip check` и `git diff --check` прошли.

Снимки реального браузера: [рецепт в публикации](screenshots/project-publication-recipe.png),
[скопированный рецепт открыт вторым аккаунтом](screenshots/project-copied-recipe.png).
Однотонные изображения этапов — синтетические PNG для проверки, не фотографии
пользователя. `main.py` запускался из другой рабочей папки с временной папкой
данных; реальные письма не отправлялись. Ресурсы Flutter и шрифтов получены
через Requests с проверкой TLS, поскольку Chromium среды не доверяет
сертификату её прокси.

Публикации, проекты и смеси остаются локальными даже при серверной авторизации.
Сервер аккаунтов не хранит эту ленту. Для обмена между устройствами ещё нужны
серверное сообщество и синхронизация. Также не реализованы модерация с причиной
и журналом, push, автодополнение тегов, связь с избранным уроком/3D-моделью,
полноценные конкурсы, 3D-просмотр и остальные ранее отмеченные требования.
Они не исключены из ТЗ. Видео личного проекта этим этапом не добавлены.

Android и отдельное окно Windows этим этапом не проверены; APK не пересобирался.
