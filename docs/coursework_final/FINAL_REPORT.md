# Итоговый отчёт — Lepka Helper 0.18.0

Оценка готовности: **PARTIAL**. Доступные испытания выполнены на изолированных данных. Для заявления о полной готовности Android нужна приёмка на устройстве; первоначальное ТЗ содержит также отсутствующие возможности. Дата подготовки: 03.11.2026.

## Состав и изменения

Клиент Python/Flet, Android-оболочка Flutter с собственным мостом камеры/файлов/уведомлений, FastAPI API и SQLite. Встроены 6 уроков и 6 моделей, 12 базовых цветов; доступны личные проекты, смеси, импорт OBJ, редактируемый учебный каталог, общее сообщество, конкурсы, роли и модерация, уведомления, русский/английский, резервирование и ограниченная офлайн-работа. Полные фактические границы — [требования](FUNCTIONAL_REQUIREMENTS.md).

Финальный этап:

- Исправлена кнопка создания публикации из конкурса: вместо возврата на главную открывается полная форма с выбранным конкурсом. После публикации возвращается обновлённый список участников.
- Общая форма публикации вынесена в единый обработчик; показывается загрузка, повторный вход использует уже открытую страницу. Запоздалое завершение не обновляет интерфейс другого аккаунта.
- Добавлены 3 проверки перехода, повторных открытий и смены аккаунта; усилена прежняя проверка конкурса. Подпись перехода переводится на английский.
- Версия обновлена до 0.18.0; схема БД, существующие данные и протокол совместимости не изменены. Нет нового обхода регистрации и нет декоративного редизайна.
- Подготовлены полная инвентаризация, технические документы, руководство, тест-кейсы, два сценария защиты и импортируемые демонстрационные файлы. Пакеты формируются по явным спискам без личных баз/сессий/ключей.

## Найденная ошибка и подтверждение исправления

Обработчик конкурса устанавливал выбранный конкурс, но открывал `/home`; новый интерфейс не открывал форму создания. Старый тест вручную создавал форму и маскировал ошибку. Сравнение старого и нового обработчика на отдельных тестовых данных даёт FAIL → PASS: [доказательство](evidence/challenge_regression.json). Новый тест проходит весь путь через настоящую кнопку, фото и публикацию. Браузер B05 подтверждает тот же путь через реальный HTTP API.

## Ограничения и невыполненное ТЗ

- **NOT READY:** вход Google OAuth, FCM и гарантированные удалённые push в течение 30 секунд отсутствуют. AR не реализована (в исходном ТЗ оговорена как необязательная).
- **PARTIAL:** импорт 3D ограничен OBJ/MTL ZIP без текстур; glTF/USDZ не поддерживаются. Смесь — взвешенный RGB, без физической модели пигментов.
- **PARTIAL:** личный снимок переносит поддерживаемые данные, но новые фотореференсы и личные данные редактируемого каталога в него не включены. Он не заменяет полный backup БД.
- **PARTIAL:** Android локальные напоминания реализованы через alarms; точность зависит от ОС, реальная доставка не испытана. Требования ТЗ к нагрузке/скорости на эталонном устройстве не измерялись.
- **BLOCKED средой / NOT TESTED:** нет физического Android и доступа к домашнему роутеру; нет настроенного почтового отправителя и двух принадлежащих оператору email для живой регистрации. Тестовые изолированные аккаунты не являются обходом регистрации в поставляемом приложении.
- SQLite и резервные копии не шифруются целиком. Серверный токен Android хранится через Keystore; это не шифрование всей БД. Учебная debug-подпись не равна публикации в магазине.

## Что сделать вручную перед защитой

Выполнить M01–M10 из [TEST_CASES](TEST_CASES.md), записать модель Android/версию ОС и действительный результат. Установить APK поверх прежней версии, не удаляя данные; проверить вход после холодного запуска, фото/камеру с увеличением, сохранение PNG/PDF с ненулевым размером, native Back, импорт файлов, уведомления/отказ разрешений и две реальные сессии через Wi-Fi. Для регистрации/восстановления отдельно настроить Resend и пользоваться собственными email. Если второго аккаунта/почты нет, не выдавать один тестовый аккаунт за многопользовательскую живую демонстрацию: показать зафиксированное автоматизированное доказательство и назвать ограничение.

## Команды и материалы

Из корня полной копии проекта, Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m scripts.run_wifi_server --data-dir "$HOME\LepkaHelperServer" --check
.\.venv\Scripts\python.exe -m scripts.run_wifi_server --data-dir "$HOME\LepkaHelperServer"
```

Сервер оставить запущенным. Другой терминал — независимый клиент ПК:

```powershell
$env:LEPKA_DATA_DIR = "$HOME\LepkaDefenseClientA"
$env:LEPKA_API_URL = "http://192.168.1.10:8000"
$env:LEPKA_ALLOW_LOCAL_API = "1"
.\.venv\Scripts\python.exe main.py
```

Заменить IPv4 на адрес своего ПК. Чисто локальный резерв запускается `main.py --local`; он не демонстрирует общее сообщество. Обе команды запускают существующий механизм, не требуют Docker. Почтовые переменные, серверная установка без GUI, резервирование, сборка и установка APK подробно в [DEPLOYMENT](DEPLOYMENT.md).

Воспроизведение доступных проверок и инвентаризации:

```powershell
.\.venv\Scripts\python.exe -m scripts.run_final_checks --output "$HOME\LepkaEvidence\tests.json"
.\.venv\Scripts\python.exe -m scripts.generate_final_inventory --output "$HOME\LepkaEvidence\inventory"
.\.venv\Scripts\python.exe -m scripts.generate_coursework_demo --output "$HOME\LepkaEvidence\demo"
```

Каталог для demo должен быть новым/пустым. Все подготовленные документы перечислены в [README](README.md); основной пользовательский маршрут — [руководство](USER_GUIDE.md), подготовка выступления — [DEMO_SCENARIO](DEMO_SCENARIO.md). Исходные `docs/ТЗ` и `docs/Plan` сохранены без изменений.

**Вывод:** проверенная локальная демонстрация кода и клиент-серверных сценариев подготовлена; полное выполнение исходного ТЗ и приёмка на физическом Android пока не подтверждены. Статус всего проекта остаётся PARTIAL.
