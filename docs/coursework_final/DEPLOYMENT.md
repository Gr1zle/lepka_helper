# Развёртывание и сборка

Состояние 0.19.0. Ниже команды для PowerShell/Windows; их синтаксис основан на текущих CLI. Финальные тесты и сборка выполняются в Linux-среде; эти команды **не являются протоколом запуска на Windows**. Не удаляйте текущие каталоги данных и не копируйте чужую SQLite поверх своей.

## 1. Исходники и Python

В GitHub используйте ветку `release/coursework-final` (она продолжает изменения №33). Для готового показа можно взять APK и серверный ZIP из финальной поставки, не устанавливая Flutter. Установите Python 3.12 x64 и Git; проверьте `py -3.12 --version`.

Из корня полного репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Активация venv не нужна. `flet[web]` 0.28.3 и версии FastAPI/Starlette из файла должны устанавливаться совместно; не обновляйте Flet до 0.80+ перед защитой.

## 2. API без Docker и хостинга

Для отдельного серверного пакета или из полного проекта:

```powershell
py -3.12 -m venv .server-venv
.\.server-venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.server-venv\Scripts\python.exe -m scripts.run_wifi_server --data-dir "$HOME\LepkaHelperServer" --port 8000
```

Это одна Uvicorn-служба на `0.0.0.0:8000`, работающая пока открыто окно. `accounts.db` создаётся/мигрирует в явно выбранном каталоге. Для существующего сервера передайте именно прежний `--data-dir`. Остановка Ctrl+C. Повторный запуск — последняя команда. `0.0.0.0` — адрес привязки, не адрес для телефона.

Проверка на ПК:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/ready
```

Ожидание: `status=ok` и `status=ready`. `/health` проверяет процесс, `/ready` — доступность нужных таблиц. Описание API находится на `/docs`; файл контрактов включён в документацию.

Если нужен существующий публичный учебный вход, после запуска API в другом окне:

```powershell
.\.server-venv\Scripts\python.exe -m scripts.create_server_demo --data-dir "$HOME\LepkaHelperServer"
```

Скрипт создаёт только предусмотренный проектом учебный аккаунт в уже существующей базе и не заменяет пароль существующего. Его общеизвестные учебные реквизиты описаны CLI; это не регистрация с доставкой email и не способ создать двух разных авторов. Для двух авторов подготовьте два обычных подтверждённых аккаунта через регистрацию. Не вводите рабочие пароли реальных сервисов в учебную HTTP-сеть.

## 3. Почтовые коды и два аккаунта

Resend используется по HTTPS. Требуются собственный API-ключ, допустимый отправитель и возможность доставки выбранным учебным адресатам. Настройте переменные только в локальном окне/секретном хранилище оператора, не в репозитории:

```powershell
$env:LEPKA_MAIL_API_KEY = "<ваш_ключ_Resend_вне_git>"
$env:LEPKA_MAIL_FROM = "Учебное приложение <verified-sender@example.com>"
.\.server-venv\Scripts\python.exe -m scripts.run_wifi_server --data-dir "$HOME\LepkaHelperServer"
```

В строках выше стоят **шаблоны**, не рабочие значения. `verified-sender@example.com` нужно заменить допустимым отправителем своего кабинета; домен example.com не отправляет вашу почту. Ограничения тестового отправителя Resend могут не позволить доставку произвольным адресатам. Без настройки новые аккаунты/восстановление не смогут получить код. В этой приёмке реальные письма не отправлялись.

Почтовые уведомления сообщества включаются отдельно параметром `--notification-mail` и личной настройкой пользователя. Отправка кодов аккаунта не требует включения этой очереди. Обычный Python-launcher не загружает `.env` автоматически; пример `.env` относится прежде всего к Compose/ручной настройке окружения.

## 4. Wi-Fi и Windows Firewall

На ПК выполните `ipconfig` и найдите IPv4 активного адаптера, например 192.168.1.20. Телефон и ПК должны быть в одной доступной сети; гостевая изоляция клиентов может мешать. ПК допустимо подключить кабелем к тому же роутеру.

Разрешите Python/входящий TCP 8000 для **частной** сети в Windows Defender Firewall. При необходимости оператор в PowerShell администратора может создать правило:

```powershell
New-NetFirewallRule -DisplayName "Lepka Helper API" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Private
```

С телефона сначала откройте `http://IPv4_ПК:8000/ready` в браузере. Затем в APK: «Подключение к серверу / Wi-Fi» → тот же адрес без `/ready` → разрешить HTTP своей сети → «Проверить связь» → «Сохранить» → вход. `localhost`/127.0.0.1 на телефоне указывает на телефон. После изменения сервера нужно войти заново. Если IP меняется, измените адрес в приложении или закрепите его на роутере.

## 5. Клиент на компьютере

В полном проекте, в другом окне PowerShell:

```powershell
$env:LEPKA_DATA_DIR = "$HOME\LepkaHelperClient-A"
$env:LEPKA_API_URL = "http://127.0.0.1:8000"
$env:LEPKA_ALLOW_LOCAL_API = "1"
.\.venv\Scripts\python.exe main.py --port 8550
```

Вторая независимая клиентская папка и порт нужны для проверки изоляции:

```powershell
$env:LEPKA_DATA_DIR = "$HOME\LepkaHelperClient-B"
$env:LEPKA_API_URL = "http://127.0.0.1:8000"
$env:LEPKA_ALLOW_LOCAL_API = "1"
.\.venv\Scripts\python.exe main.py --port 8551
```

Запускайте команды в двух разных окнах. Для разных авторов войдите разными аккаунтами. Каталоги Client-A/Client-B и Server должны различаться. `main.py` запускает веб-клиент на loopback; это резерв демонстрации на самом компьютере, не общедоступный веб-сайт для телефона. Сохранённый `server_connection.json` имеет приоритет над переменной адреса; если он указывает на другой сервер, исправьте подключение через UI. Не выбирайте «Локальный режим», если демонстрируете общую ленту.

Полностью локальный резерв без API:

```powershell
$env:LEPKA_DATA_DIR = "$HOME\LepkaHelperLocalDemo"
.\.venv\Scripts\python.exe main.py --local --port 8552
```

Он проверяет локальные проекты/цвета/уроки/3D, но **не** общее сообщество. Для отдельного настольного окна нужны desktop-компоненты Flet той же версии и `main.py --desktop`; текущая основная проверка ПК — браузерная.

## 6. Сборка APK на Windows

Готовый APK предпочтителен для защиты. Для самостоятельной воспроизводимой сборки нужны Git, Python 3.12 x64, JDK 17, Flutter 3.29.2, Android SDK с platforms/android-35, build-tools 34.0.0 и NDK 25.1.8937393. Эти версии использованы в проверенной сборочной среде. Примите Android SDK licences командой `flutter doctor --android-licenses`, проверьте `flutter doctor -v`. Установите совместимые Command-line Tools через Android Studio. Обеспечьте доступ к PyPI, Flet Android wheels, pub.dev, Maven/Google; корпоративному прокси может потребоваться его CA.

```powershell
.\.venv\Scripts\python.exe -m pip install flet-cli==0.28.3
$BuildFlet = (Resolve-Path .\.venv\Scripts\flet.exe).Path
.\.venv\Scripts\python.exe scripts\prepare_android.py --output ..\lepka-android-019 --api-url=
Set-Location ..\lepka-android-019
& $BuildFlet build apk --build-version 0.19.0 --build-number 16 --verbose
```

Каталог `lepka-android-019` должен быть новым. `--api-url=` намеренно пуст: адрес Wi-Fi задаётся в UI установленного приложения. Не подставляйте HTTP в `--api-url` — текущий packager допускает там только HTTPS либо пустую строку. Прямой `flet build apk` из корня полного репозитория может упаковать лишние серверные/локальные файлы; используйте подготовленный каталог. Сохраните `build/flutter-packages`, локальный wheel и закреплённые media_kit/screen_brightness overrides из pyproject. Flet CLI может сам скачать минимально совместимый Flutter, но заданный Flutter 3.29.2 делает окружение определённым.

Результат — `build\apk\app-arm64-v8a-release.apk`. Из-за split-per-ABI код ARM64 должен быть 2016 при базовом build-number 16; версия проверяется через `aapt dump badging`, подпись — `apksigner verify --print-certs`. Проверить SHA-256 можно `Get-FileHash <путь-к-apk> -Algorithm SHA256`. Для обновления существующей установки необходимы тот же package и сертификат. Чужая сборочная машина с новым debug-keystore не обязана подписать файл тем же ключом: не удаляйте приложение с пользовательскими данными ради обхода несовместимой подписи; используйте опубликованный подписанный APK или прежний keystore оператора. Приватный ключ в комплект не входит. Это учебная подпись, не выпуск в Google Play.

## 7. Установка и проверка Android

Скопируйте готовый APK на устройство, разрешите установку из выбранного источника и установите **поверх** старой версии. Альтернатива при подключённом ADB:

```powershell
adb devices
adb install -r "<путь-к-проверенному-APK>"
```

ADB serials/установка в текущей среде не проверены: подключённых устройств нет. После установки проверьте версию, вход, адрес API, `/ready`, один пост со второго аккаунта и сохранение личного проекта после полного перезапуска. Затем выполните аппаратный чек-лист из TEST_CASES. Удаление приложения удаляет его внутреннюю SQLite и внутренние копии.

## 8. Резервная копия и восстановление сервера

```powershell
.\.server-venv\Scripts\python.exe -m scripts.server_backup backup --source "$HOME\LepkaHelperServer\accounts.db" --output "$HOME\LepkaBackups\before-defense.db"
```

Выходной файл должен быть новым. Используется SQLite backup, а не простое копирование открытого файла. Восстановление создаёт новый файл и отзывает сохранённые сессии/коды:

```powershell
.\.server-venv\Scripts\python.exe -m scripts.server_backup restore --source "$HOME\LepkaBackups\before-defense.db" --output "$HOME\LepkaRestored\accounts.db"
```

Остановите старый сервер и запустите API с `--data-dir "$HOME\LepkaRestored"`; войдите заново. Не заменяйте действующую базу без независимой копии. Резервная копия содержит персональные данные и хеши аккаунтов, не публикуйте её в GitHub.

## 9. Переменные и диагностика

| Переменная | Назначение / граница |
|---|---|
| LEPKA_DATA_DIR | Отдельная клиентская папка; в APK штатно FLET_APP_STORAGE_DATA |
| LEPKA_SERVER_DATA_DIR | Папка accounts.db API; launcher также принимает --data-dir |
| LEPKA_API_URL | Начальный адрес клиента при отсутствии сохранённой настройки |
| LEPKA_ALLOW_LOCAL_API | Разрешение loopback HTTP для ПК/интеграционной проверки; APK разрешает свою LAN через UI |
| LEPKA_FORCE_LOCAL | Явный локальный режим; `main.py --local` устанавливает его |
| LEPKA_MAIL_API_KEY / LEPKA_MAIL_FROM | Секрет/отправитель Resend, только на сервере |
| LEPKA_NOTIFICATION_MAIL_ENABLED | Опциональная очередь почтовых событий; launcher --notification-mail |

Список не означает, что в APK нужен почтовый ключ. Он туда не включается.

| Проблема | Проверка и действие |
|---|---|
| Телефон не видит сервер | /ready с телефона, IPv4, порт, Firewall Private, гостевая сеть/изоляция, включён ли ПК |
| Вход по тестовым данным не проходит | Убедиться, что demo создан именно в используемой accounts.db; другой сервер/локальная база имеют свои аккаунты |
| Не приходит код | Почтовые env, допустимый отправитель/получатель Resend, спам, срок/лимит; реальные коды не искать в логах |
| «Сессия завершена» | Срок 12 часов, отзыв после пароля/роли/восстановления; повторный вход |
| Пост долго грузится | Сервер 0.17+, один тап, индикатор; проверить сеть/перезапуск сервера; не создавать 30 нажатий |
| Не сохраняется фото/PNG | Формат/размер, разрешения и провайдер папки Android; повторить в другой папке, проверить ненулевой файл |
| Камера в браузере недоступна | getUserMedia требует безопасный контекст HTTPS/localhost; использовать загрузку фото или нативный APK |
| Видео не играет | MP4 H.264/AAC, размер/структура, кодеки устройства; веб-резерв использует отдельный браузерный проигрыватель |
| APK не устанавливается | ARM64 и Android 9+, место, подпись/package, запрет источника; не удалять старое приложение без копии |
| Сборка сломалась после обновления | Вернуть точные версии requirements/Flutter/JDK/SDK и pyproject overrides; новый чистый подготовленный каталог |

Честный статус аппаратных пунктов и публичного HTTPS: NOT TESTED; наличие этих инструкций не является выполненным испытанием.
