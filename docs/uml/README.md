# UML-диаграммы классов Lepka Helper

Диаграммы получены **Pyreverse из Pylint 3.3.9 / Astroid 3.3.11** по исходникам версии 0.18.0, commit `582790ea0041c42ab0b381b5da58e85de25afb34`. Рендеринг: Graphviz 2.42.4. Код приложения не изменён.

**53 класса, 22 связи наследования, 2 связи между полями и классами.** Подготовлены общая схема и **10 подробных схем подсистем**. В подробных схемах сохранены поля, методы и параметры, включая закрытые/служебные методы. Методы родителей не дублируются в каждом наследнике. Обзор содержит только названия классов, без полей/методов.

[Скачать всё одним ZIP](https://github.com/Gr1zle/lepka_helper/raw/refs/heads/artifacts/android-demo-20261031/lepka-uml-pyreverse-0.18.0.zip).

## Файлы и форматы

- `raw/classes_LepkaHelper.dot` и `.puml` — **неизменённый исходный вывод Pyreverse**: полная диаграмма классов. DOT редактируется как текст и открывается в Graphviz; PUML — в PlantUML.
- `editable/*.dot` — редактируемые схемы подсистем и обзор с оформлением для документации. Никакие классы или связи исходного графа не потеряны при разделении.
- `images/*.svg` — векторные изображения для Word 2019/2021/Microsoft 365. Предпочтительный вариант: качество не теряется при масштабировании.
- `images/*.png` — растровые изображения с метаданными **300 dpi**, для Word, который не поддерживает SVG.
- `images/*.pdf` — векторные листы для просмотра/печати; для вставки в Word удобнее SVG/PNG.
- [CLASS_INDEX.md](CLASS_INDEX.md) — все классы, файлы и строки определения, родители, принадлежность подсистеме.
- [manifest.json](manifest.json) — commit, версии инструментов, полный список входных файлов и SHA-256, классы/связи, размеры PNG, контрольные суммы диаграмм.
- [VALIDATION.md](VALIDATION.md) — выполненные проверки файлов и соответствия исходникам.
- [pyreverse.log](pyreverse.log) — фактически выполненные параметры и вывод генератора. Полный список 141 входного файла — в manifest.
- [generate.py](generate.py) и [requirements-tools.txt](requirements-tools.txt) — воспроизводимая генерация.

## Как вставить в Word

1. Скачайте ZIP и распакуйте. Используйте отдельные схемы 01–10 для разделов работы. Схема 00 предназначена для обзора/приложения; все детали на один лист с ней помещать не нужно.
2. Word → **Вставка → Рисунки → Это устройство** → выберите нужный SVG. Если Word его не принимает, выберите одноимённый PNG.
3. Сохраняйте пропорции изображения. Для насыщенных схем используйте отдельную страницу с подходящей ориентацией; не уменьшайте подписи до нечитаемого размера. Вектор можно увеличивать и размещать на нескольких страницах.
4. Для PNG при необходимости: Файл → Параметры → Дополнительно → Размер и качество изображения → «Не сжимать изображения в файле» / высокая точность. Не копируйте уменьшенное превью из браузера — вставляйте скачанный оригинал.
5. Добавьте подпись, например: «Рисунок N — Диаграмма классов подсистемы публикаций и комментариев». Редактировать состав/связи нужно в DOT/PUML, затем повторно отрендерить изображение; SVG в Word не является исходной UML-моделью.

## Что включено и исключено

Входные файлы выбираются по явным корням: Python-файлы корня проекта, `views`, `backend`, `scripts`. В служебных скриптах есть один самостоятельный класс `scripts.generate_learning_models.Builder`; он вынесен в лист 10. Анализируются также исходники, оставленные для совместимости; наличие класса на диаграмме не доказывает, что он сейчас используется в каждом режиме приложения.

Исключены `tests`, тестовый runner `scripts/run_final_checks.py`, документация/генератор диаграмм, виртуальные окружения, `site-packages`, сторонние библиотеки и каталоги сборки. Их классы не добавлены как узлы графа. Java/Dart-код `native/` не анализируется: Pyreverse работает с Python. Собственный Python-мост `ProtectedSession` включён.

При наследовании от внешнего класса его имя сохранено в подписи `base: ... [external]`, но отдельного узла библиотеки нет. Это относится также к стандартным `Exception`/`ValueError`. Например, Pydantic `BaseModel` и Flet `Control` не развёрнуты в диаграммы сторонних библиотек.

Большая часть предметной логики проекта реализована функциями и SQLite/словарями. Поэтому здесь нет выдуманных классов `Project`, `User`, `ColorMixture` и связей ORM. Диаграмма классов не заменяет [ER-диаграмму базы](../coursework_final/ER_DIAGRAM.mmd) или граф вызовов функций.

## Связи и ограничения статического анализа

- Пустой треугольник направлен **от наследника к родителю**. Все 22 внутренних отношения Pyreverse сопоставлены с фактическими объявлениями родителей в AST.
- Связь `NoticeCenter.community` с `ChallengeClient` найдена Pyreverse по присваиванию `self.community = ChallengeClient(user)`. Сохранён его ромб у `NoticeCenter`, аналогичный исходному DOT/PUML. Это результат классификации инструмента; время жизни объектов отдельно не доказывалось.
- **Одна явно помеченная обработка после Pyreverse:** Pyreverse 3.3.9 не вывел ребро для `PostInput.photos: list[PhotoInput]`. Генератор автоматически восстанавливает только явные аннотации полей, ссылающиеся на собственные классы проекта. На схемах 00/03 добавлена ассоциация `PostInput → PhotoInput`, подпись `photos [1..10]`, по `Field(min_length=1, max_length=10)`. Происхождение записано в `manifest.annotatedAssociations`; исходные файлы в `raw/` не подменяются. Это не придуманная зависимость и не утверждение о композиции.
- Пунктирных «зависимостей» между всеми импортируемыми модулями или вызываемыми функциями не добавлялось. Отсутствие ребра у независимого класса не означает отсутствия его использования приложением.
- Показанные типы — аннотации и статический вывод Astroid. Неточно выведенный `NoneType`/неуказанный тип не является гарантией runtime-типа; значения/БД приложения не исполнялись и не читались.

## Повторная генерация (Windows PowerShell)

Нужны Python 3.12 и установленный Graphviz (`dot -V` должен работать; например, `winget install Graphviz.Graphviz`, затем новое окно терминала). Для русского текста желательно наличие DejaVu Sans либо совместимого шрифта с кириллицей.

Из корня полной копии репозитория:

```powershell
py -3.12 -m venv ..\lepka-uml-tools
..\lepka-uml-tools\Scripts\python.exe -m pip install -r docs\uml\requirements-tools.txt
..\lepka-uml-tools\Scripts\python.exe docs\uml\generate.py --pyreverse ..\lepka-uml-tools\Scripts\pyreverse.exe
```

Архив с диаграммами не содержит исходники приложения: для повторной генерации поместите его файлы в `docs/uml` полной копии проекта. Зависимости приложения устанавливать для этого не требуется; инструменты используют собственное окружение. Исходники приложения не импортируются для выполнения и не изменяются. При запуске Pyreverse статически разрешает импорты через Astroid; классы за пределами входного набора проверяются и исключаются из результата.

Генератор перезаписывает только свои результаты в `docs/uml`. Он останавливается с ошибкой при пропущенном классе, потерянном наследовании или ребре, а также если исходные Python-файлы изменились во время генерации. При добавлении новых модулей с классами нужно явно распределить их в `GROUPS` в генераторе.

Linux/macOS: отдельный venv, `python -m pip install -r docs/uml/requirements-tools.txt`, затем `python docs/uml/generate.py --pyreverse /absolute/path/to/venv/bin/pyreverse`. Только перерисовка отредактированного DOT:

```powershell
dot -Tsvg docs\uml\editable\03_server_community.dot -o docs\uml\images\03_server_community.svg
dot -Tpng -Gdpi=300 docs\uml\editable\03_server_community.dot -o docs\uml\images\03_server_community.png
```

Повторная генерация Pyreverse перезапишет ручные исправления производных DOT; для своих вариантов сохраняйте отдельные имена/копии. Восстановленная связь фотографии отмечена отдельно, а полный исходный вывод Pyreverse всегда доступен в `raw/`.
