# Android: возврат цвета и внешний экспорт JSON — 0.19.0

Патч продолжает финальную поставку 0.18.0 и материалы UML. Схема БД и серверный протокол не меняются. Команды оператора: [CONSOLE_COMMANDS.md](../CONSOLE_COMMANDS.md).

## Изменения

- Полноэкранное фото открывается внутри того же диалога выбора цвета. «Готово» восстанавливает его обычный вид с заголовком «Цвет с камеры или фото», выбранный образец сохраняется. «В целевой HEX» переносит его в подбор; «Добавить ближайший цвет» добавляет ближайший базовый цвет. Переключение страниц/закрытие и повторное открытие модального маршрута больше не используются.
- «Экспорт JSON» проекта и «Экспорт полного JSON» личных данных используют общий экспорт байтов: Android открывает системное «Сохранить как», браузер скачивает файл, настольное приложение предлагает файл с атомарной записью. MIME — application/json; имена lepka-project.json и lepka-personal.json.
- Android-мост теперь разрешает JSON до 20 МБ, включая изображения/модели, как ограничивает формат архива. PNG/PDF сохраняют прежний предел 10 МБ. После записи провайдеру Android файл перечитывается: проверяются длина и SHA-256. Отмена не считается успехом, ошибка записи не оставляет заведомо испорченный новый документ.
- Старые копии внутри приложения не удаляются. При экспорте проекта сохраняется прежняя внутренняя копия и дополнительно открывается системное сохранение файла. Для личных данных отдельная команда «Создать полную личную копию» по-прежнему доступна.
- Добавлена краткая инструкция PowerShell: установка, параметры запуска, Wi-Fi и Firewall, тестовый вход, назначение первого администратора, Resend, backup/restore, клиент ПК.

## Проверки

Добавлены 3 регрессии: реальный JSON проекта отправляется в Android document writer; полный личный JSON отправляется туда же и корректно отменяется; три последовательных возврата из полноэкранного фото сохраняют диалог/образец, повторное «Готово» не меняет навигацию. Прежний тест выбора цвета обновлён под один модальный маршрут.

**521 автотест PASS, 0 FAIL**, включая восстановление прежних внутренних копий проектов. [JSON-протокол](android_final_evidence/tests.json). Браузер: три цикла полного фото и применения HEX на ширинах 390/320 px, фактические скачивания и разбор обоих JSON — PASS. [Протокол](android_final_evidence/browser.json), [снимки](android_final_evidence/screenshots/). Настоящая камера и системное сохранение Android в браузере не проверяются.

Особенность среды сборки: Flutter/Gradle успешно создали подписанный APK, но окончательное копирование Flet CLI остановилось из-за заполнения диска рабочего окружения. После проверки исходного APK удалены только промежуточные сборочные файлы, готовый APK скопирован побайтово; SHA-256 совпал. Это не подмена APK веб-запуском.

Установить поверх прежнего APK, приложение не удалять. Для проверки:

1. Цвета → Подобрать → Сканировать цвет → загрузить фото → во весь экран → увеличить/коснуться оттенка → Готово. Должен остаться диалог с выбранным образцом. Нажать «В целевой HEX» и проверить цвет; повторить несколько раз.
2. Проект → Экспорт JSON → выбрать папку/имя в Android → сохранить. Проверить ненулевой размер и импорт этого файла как новой копии проекта. Исходный проект должен остаться.
3. Профиль → Настройки → Личные данные и синхронизация → Экспорт полного JSON → сохранить. Для проверки JSON не нужно заменять действующие личные данные; восстановление выполнять только на запасном наборе после независимой копии.
4. Повторить выбор папки с отменой. Отмена не должна сообщать об успешном сохранении.

Команды запуска/readiness, создания тестового пользователя, назначения администратора (включая повтор), резервной копии и восстановления дополнительно выполнены через CLI на новой временной базе: [протокол](android_final_evidence/console.json). Существующие пользовательские базы не использовались; письма отключены. PowerShell/Windows отдельно не запускался.

Браузерная приёмка и имитация Android-моста не являются физической проверкой Android SAF, камеры и системного Back. В среде нет подключённого телефона; эти пункты остаются NOT TESTED. Реальные письма также не отправлялись. Ограничения исходного ТЗ (Google OAuth, FCM и т. д.) остаются в [финальном отчёте](coursework_final/FINAL_REPORT.md).
