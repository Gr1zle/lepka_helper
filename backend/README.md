# Сервер аккаунтов

Сервер использует FastAPI и существующие сервисы аккаунтов. Интерфейс Flet обращается
к нему через `account_gateway.py`. Генерация и проверка почтовых кодов, пароли,
сессии и профиль выполняются на сервере. Ключ Resend задаётся только процессу сервера.

## Локальная проверка на Windows

Команды выполняются из корня репозитория, Python 3.12 и зависимости уже должны быть
установлены по основному README. Нужны два отдельных терминала PowerShell.

Терминал сервера:

```powershell
$env:LEPKA_SERVER_DATA_DIR = Join-Path $env:LOCALAPPDATA "LepkaHelperServer"
$mailKey = Read-Host "Ключ Resend" -AsSecureString
$env:LEPKA_MAIL_API_KEY = [System.Net.NetworkCredential]::new("", $mailKey).Password
$env:LEPKA_MAIL_FROM = "onboarding@resend.dev"
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Если домен Resend уже подтверждён, замените отправителя адресом этого домена.
Тестовый отправитель `onboarding@resend.dev` отправляет только на почту вашего
аккаунта Resend. Не вводите ключ прямо в команду, исходный код или JSON-конфигурацию.
После остановки сервера можно удалить переменную из терминала:
`Remove-Item Env:LEPKA_MAIL_API_KEY`, затем `Remove-Variable mailKey`.

Терминал клиента:

```powershell
Remove-Item Env:LEPKA_MAIL_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:LEPKA_MAIL_FROM -ErrorAction SilentlyContinue
$env:LEPKA_API_URL = "http://127.0.0.1:8000"
$env:LEPKA_ALLOW_LOCAL_API = "1"
$env:LEPKA_DATA_DIR = Join-Path $env:LOCALAPPDATA "LepkaHelperClientServerMode"
.\.venv\Scripts\python.exe main.py
```

HTTP разрешён только с явным `LEPKA_ALLOW_LOCAL_API=1` и адресом `127.0.0.1`,
`localhost` или `10.0.2.2`. Последний адрес предназначен для разработки с Android
Emulator; работа на эмуляторе этим этапом не проверялась. Для настоящего устройства
и размещённого сервера используйте HTTPS с действительным сертификатом.

База сервера — `accounts.db` в `LEPKA_SERVER_DATA_DIR`. Если папка не задана, сервер
не запустится. База клиента — `lepka_helper.db` в `LEPKA_DATA_DIR`.
Существующая пользовательская база не заменяется и не загружается на сервер.

Сервер начинает с пустой базы, демонстрационный аккаунт не создаётся. Зарегистрируйте
аккаунт, запросите код и подтвердите почту. В тестовом режиме Resend используйте
свою почту. Если письмо не отправилось, повторите через «Подтвердить регистрацию».
Старый локальный пароль автоматически не переносится на сервер.

## Проверка поведения

1. Пройдите регистрацию с подтверждением кода, войдите и сохраните профиль и настройки.
2. Откройте вторую сессию. Измените пароль в первой: следующее действие во второй
   должно завершить её сессию и открыть вход.
3. Проверьте восстановление пароля и изменение email. Старый код повторно не принимается.
4. Остановите сервер: клиент должен показать сетевую ошибку, без перехода к локальному входу.
5. Перезапустите сервер с той же папкой: аккаунт и настройки должны сохраниться.
6. Для удаления используйте специально созданный тестовый аккаунт и подтвердите пароль.

Все запросы профиля и аккаунта определяют владельца из Bearer-токена.
Поля `userId`, `roleName` и другие незаявленные поля в теле запроса отклоняются.
При HTTP 401 интерфейс очищает сессию. Сетевая ошибка сама по себе не отзывает токен. Явный выход очищает сессию клиента
даже без сети; при этом интерфейс честно сообщает, что отзыв токена сервером
не подтверждён. На сервере такой токен сохраняется до истечения срока действия.

Список API и схемы доступны по пути `/docs`, проверка готовности — `GET /health`.
Пароли и коды передаются только в JSON-теле, токен — в заголовке Authorization.
В ответе ошибки валидации не возвращается введённое значение поля.

## Docker

Сборка из корня репозитория:

```sh
docker build -f backend/Dockerfile -t lepka-accounts:local .
docker volume create lepka-accounts-data
docker run --name lepka-accounts -p 127.0.0.1:8000:8000 \
  -v lepka-accounts-data:/data \
  -e LEPKA_MAIL_API_KEY -e LEPKA_MAIL_FROM lepka-accounts:local
```

Перед запуском переменные почты должны быть заданы в терминале или секретах
хостинга. Флаги `-e` здесь передают значения из окружения, без записи ключа в команду.
Не передавайте ключ через build-arg: сборке он не нужен. Образ копирует только серверные
модули; `.dockerignore` исключает `.env`, базы и файлы сборки из контекста.
Сервер запускается от непривилегированного пользователя. Том `/data` сохраняйте
между перезапусками и обновлениями; удаление тома уничтожит серверную базу.

Если сборочная среда использует HTTPS-прокси со своим CA, Dockerfile поддерживает
передачу доверенного CA только на время установки зависимостей:

```sh
docker build --secret id=ca_bundle,src=/path/to/trusted-ca-bundle.pem \
  -f backend/Dockerfile -t lepka-accounts:local .
```

Это сертификаты доверия среды, а не ключ Resend. Проверка TLS остаётся включённой.
Обычному хостингу без такого прокси этот параметр не нужен.

## Размещение и Android

Для размещения нужен постоянно доступный сервер с Python 3.12 либо Docker,
постоянный диск для SQLite и HTTPS перед API. Бесплатный хостинг с непостоянным
диском не обеспечивает сохранность аккаунтов. Запускайте один worker; счётчик
30 публичных POST-запросов `/auth/` в минуту с одного IP хранится в памяти процесса.
Ограничения неправильных паролей и кодов дополнительно хранятся в SQLite.

На хостинге задаются `LEPKA_MAIL_API_KEY`, `LEPKA_MAIL_FROM` и каталог данных сервера.
Reverse proxy должен завершать HTTPS; внутренний порт 8000 не открывается для
прямого публичного доступа. При передаче реального IP настройте доверие к конкретному
proxy, чтобы IP-ограничения не применялись ко всем клиентам как к одному адресу.

Клиент получает только публичный адрес API. В `assets/client_config.json`:

```json
{"apiBaseUrl": "https://api.your-host.example"}
```

Замените пример реальным HTTPS-адресом. Из переменных окружения `LEPKA_API_URL`
имеет приоритет над файлом. Для возврата прежнего локального режима на ПК уберите
переменную API и оставьте пустой `apiBaseUrl`. Android без адреса API не запускает
локальные сценарии аккаунта.

В конфигурации клиента допустим только `apiBaseUrl`. Ключ Resend в неё не помещается.
При будущей сборке APK исключите серверные данные, `.env`, виртуальное окружение и
личные базы из пакета; наличие `.gitignore` само по себе не проверяет состав APK.
APK и публичное HTTPS-размещение этим этапом ещё не проверены. `127.0.0.1` на телефоне
обозначает сам телефон, а не ваш компьютер.

## Границы этого этапа

- Аккаунты, коды, профиль и настройки работают через API. Проекты, смеси, уроки и
  публикации пока остаются локальными и не синхронизируются между устройствами.
- Серверные аккаунты привязываются к отдельным техническим владельцам локальных
  данных по паре «адрес API + ID сервера». Совпадение ID, email или ника со старым
  локальным аккаунтом не приводит к объединению. Меняя адрес API, вы меняете эту привязку.
- Токены находятся в памяти Flet и передаются по HTTPS; на диске клиента сохраняется
  только хеш привязки сессии. Безопасное долговременное хранилище устройства и
  «Запомнить меня» ещё не реализованы.
- Удаление аккаунта очищает его данные на сервере и данные его привязки на текущем
  клиенте. Очистка кешей других устройств не выполняется дистанционно; их токены
  больше не действуют. Файлы, выбранные пользователем с диска, не удаляются.
- Серверная загрузка аватара пока отсутствует. В серверном режиме путь файла
  устройства не сохраняется на сервере. Google OAuth и административные сценарии
  остаются открытыми требованиями.
- Полный оффлайн-режим с очередью изменений и синхронизацией не реализован.
  Сбой сервера не разрешает клиенту обходить серверную авторизацию.

ТЗ этим этапом не изменяется.
