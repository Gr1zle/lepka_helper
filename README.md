# Lepka Helper — помощник для лепки

Курсовой проект на Python, Flet и SQLite. Рабочая версия с локальными сервисами, проверками проектов и аккаунтов.

## Запуск на Windows

Проверенная версия Python — 3.12. В терминале VS Code, открытом в папке `lepka_helper`, выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Активировать окружение не требуется. При следующих запусках нужна только последняя команда. Если `py -3.12` сообщает об отсутствии версии, установите Python 3.12.

Приложение открывается в браузере по адресу http://127.0.0.1:8550. Для другого порта добавьте `--port 8551`.

Для отдельного окна сначала установите настольный клиент:

```powershell
.\.venv\Scripts\python.exe -m pip install "flet[desktop]==0.28.3"
.\.venv\Scripts\python.exe main.py --desktop
```

Первую проверку выполните в браузере. Отдельное окно Windows и APK пока не проверены.

## Тестовый вход

- Email: `test@email.com`
- Пароль: `Test123456`

Пользователь создаётся при первом открытии приложения. Если в существующей базе его пароль уже изменён, используйте изменённый пароль. Базу удалять не нужно.

## Структура и данные

- `main.py` — запуск и маршрутизация.
- `views/` — экраны приложения.
- `*_service.py` — функции предметной области.
- `database.py` — SQLite и запросы.
- `password_service.py` — общий формат и проверка паролей.
- `app_paths.py` — папка данных, независимая от папки запуска.
- `tests/` — проверки интерфейса Flet, проектов, аккаунтов и обновления базы.

При локальном запуске база `lepka_helper.db` и состояние `app_state.json` находятся рядом с приложением. Можно задать другую папку через `LEPKA_DATA_DIR`. В упакованной среде учитывается `FLET_APP_STORAGE_DATA`; мобильная сборка ещё не протестирована.

Приложение работает с локальными сервисами и SQLite. Сервер аккаунтов находится в `backend/`; его режим включается отдельно.

## Проверка после установки

1. Дождаться заставки. В новой копии пройти вводные экраны.
2. Войти тестовым пользователем.
3. Открыть «Главная», «Поиск», «Цвета», «Проекты», «Профиль».
4. Выйти и зарегистрировать собственный тестовый аккаунт.
5. Сменить пароль в профиле, затем выйти и войти с новым паролем.
6. Открыть «Забыли пароль?» и проверить появление диалога.

Автоматические проверки из папки `lepka_helper`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Серверный режим аккаунтов

Добавлен отдельный FastAPI-сервер и подключение интерфейса через HTTP API.
Инструкция запуска двух процессов, настройки Resend и размещения:
[backend/README.md](backend/README.md).

В серверном режиме ключ Resend задаётся только серверу. Клиенту передаётся
`LEPKA_API_URL` либо публичный HTTPS-адрес в `assets/client_config.json`.
По умолчанию адрес пуст: на ПК сохраняется прежний локальный режим.
Android без адреса сервера не запускает локальные сценарии аккаунта.

Серверная и локальная базы разделены. Старые аккаунты и данные автоматически
не переносятся. Проекты, смеси и публикации пока локальные, синхронизации нет.

## Почта и аккаунты

Для отправки писем используются две переменные окружения:

- `LEPKA_MAIL_API_KEY` — секретный ключ Resend с правом отправки писем.
- `LEPKA_MAIL_FROM` — отправитель, разрешённый в Resend, например адрес на вашем подтверждённом домене.

Задайте их вне исходного кода: в настройках облачной среды или в окружении
процесса на своём компьютере. Не добавляйте ключ в Git. При работе Resend
в тестовом режиме получатели могут быть ограничены правилами сервиса.
`python main.py` не отправляет писем автоматически.

Следующее описание локального режима относится к запуску без адреса API. В серверном
режиме эти операции выполняются сервером по инструкции выше.

Новая регистрация создаёт неподтверждённый аккаунт и открывает ввод кода.
Код подтверждения регистрации действует 24 часа. Если письмо не отправилось,
используйте «Подтвердить регистрацию» на экране входа после настройки почты.
Не нужно регистрировать тот же аккаунт заново или удалять базу.
Код восстановления и смены email действует 10 минут. Код одноразовый,
после пяти ошибок нужен новый; повторная отправка возможна через минуту.
Коды не показываются в интерфейсе и не записываются в журналы.

После пяти ошибок вход блокируется на 15 минут; после трёх ошибок текущего
пароля его смена блокируется на 5 минут. Выход отзывает текущую сессию,
смена пароля/email и восстановление пароля отзывают все сессии аккаунта.
Сессия проверяется при следующем действии в другой открытой вкладке.
Пароли в пользовательской базе не заменяются при обновлении.
Старые аккаунты сохраняют доступ; миграция не доказывает владение их почтой.

При удалении аккаунта удаляются его личные записи SQLite. Публикации заменяются
заглушками, чтобы сохранить комментарии других пользователей. Для заглушек
используется заблокированная техническая запись автора. Старые записи-сироты
автоматически не удаляются. Перед обновлением сохраните копию существующей базы.

Подробности реализации, проверки и оставшиеся ограничения: `docs/day2_stabilization.md`.

## Проверка проектов

Дедлайн необязателен. Если он указан, требуется существующая календарная дата
строго в формате `ДД.ММ.ГГГГ`, например `25.04.2026`. Пробелы по краям
убираются, прошедшие даты допускаются. Пункт 4.1.19.4 в `docs/ТЗ` допускает этот формат и пустую дату.
DatePicker из пункта 4.1.4.9 пока не реализован.

В «Проектах» проверьте следующие действия на специально созданном тестовом проекте:

1. Введите `НЕ ДАТА`, затем `31.04.2026`: сохранение должно отклоняться с сообщением.
2. Создайте проект с пустым дедлайном: в карточке появится «Без дедлайна».
3. Добавьте два этапа, отметьте один: прогресс станет 50%.
4. Удалите незавершённый этап: прогресс станет 100%.
5. Войдите в другой аккаунт: этот проект не должен отображаться.
6. Вернитесь в первый аккаунт и удалите тестовый проект: вместе с ним удаляются оставшиеся этапы.

Команда автоматических проверок приведена выше. `tests/test_projects.py`
проверяет также подстановку чужих идентификаторов на уровне сервисов и SQL,
удаление всех этапов и откат транзакции при ошибке. `tests/test_startup.py`
проверяет обработчики формы проектов с настоящими элементами Flet и транспортом
в памяти. Каждый тест использует временную SQLite-базу; пользовательская база
не удаляется и не изменяется. Ранее возникшие записи-сироты автоматически
не удаляются: для очистки старых данных нужна отдельная проверка и резервная копия.

## Текущие ограничения

В коде есть формы регистрации, профиля, смешивания цветов, проектов, уроков и публикаций. Автотесты проверяют основные переходы, аккаунты, профили, настройки и проекты; полные испытания каждой функции на Android ещё предстоят.

Google-вход не подключён. Подтверждение регистрации, смена email и восстановление пароля используют письма Resend; без настройки почты эти операции не завершатся. «Запомнить меня» пока отключено: безопасное сохранение токена на устройстве не реализовано. Язык сохраняется в настройках, но полного английского перевода нет. Публикации хранятся локально, сетевое сообщество не подключено. Экспорт смеси пока текстовый. Полноценный 3D, AR, push и серверная синхронизация не подтверждены и требуют отдельной работы. Эти требования остаются открытыми; исходное ТЗ не изменяется.
