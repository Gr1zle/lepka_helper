# Lepka Helper — помощник для лепки

Курсовой проект на Python, Flet и SQLite. Рабочая версия с локальными сервисами, проверками проектов и аккаунтов.

**Контрольная версия 0.6.0 для предварительной проверки на ПК, 29.10.2026.**
Быстрый запуск и сценарий показа: [REVIEW_START.md](REVIEW_START.md).
Проверенный состав и открытые требования: [docs/review_version.md](docs/review_version.md).
Для проверки без API запускайте `python main.py --local`; этот режим не меняет сервер и файл адреса API.

## Запуск на Windows

Проверенная версия Python — 3.12. В терминале VS Code, открытом в папке `lepka_helper`, выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Активировать окружение не требуется. При следующих запусках нужна только последняя команда. Если `py -3.12` сообщает об отсутствии версии, установите Python 3.12.

Приложение открывается в браузере по адресу http://127.0.0.1:8550. Для другого порта добавьте `--port 8551`. Используйте запуск через `main.py`: он подключает маршрут скачивания PNG-рецептов.

Для отдельного окна сначала установите настольный клиент:

```powershell
.\.venv\Scripts\python.exe -m pip install "flet[desktop]==0.28.3"
.\.venv\Scripts\python.exe main.py --desktop
```

Первую проверку выполните в браузере. Отдельное окно Windows и APK пока не проверены.

## Структура и данные

- `main.py` — запуск и маршрутизация.
- `views/` — экраны приложения.
- `*_service.py` — функции предметной области.
- `database.py` — SQLite и запросы.
- `password_service.py` — общий формат и проверка паролей.
- `app_paths.py` — папка данных, независимая от папки запуска.
- `tests/` — проверки интерфейса Flet, проектов, аккаунтов и обновления базы.

При локальном запуске база `lepka_helper.db` и состояние `app_state.json` находятся рядом с приложением. Можно задать другую папку через `LEPKA_DATA_DIR`. В упакованной среде учитывается `FLET_APP_STORAGE_DATA`; мобильная сборка ещё не протестирована.

Приложение работает с локальными сервисами и SQLite. Сервер аккаунтов находится в `backend/`; его режим включается отдельно.


## Серверный режим аккаунтов

Добавлен отдельный FastAPI-сервер и подключение интерфейса через HTTP API.
Инструкция запуска двух процессов, настройки Resend и размещения:
[backend/README.md](backend/README.md).

В серверном режиме ключ Resend задаётся только серверу. Клиенту передаётся
`LEPKA_API_URL` либо публичный HTTPS-адрес в `assets/client_config.json`.
По умолчанию адрес пуст: на ПК сохраняется прежний локальный режим.
Android без адреса сервера не запускает локальные сценарии аккаунта.

Серверная и локальная базы разделены. Старые аккаунты и данные автоматически
не переносятся. При заданном API публикации, фото, лайки, комментарии и прогресс
мастер-классов хранятся на сервере. Личные проекты, смеси и прогресс встроенных
уроков пока локальные. [Настройка общего сообщества](docs/server_community.md).

## Почта и аккаунты

Для отправки писем используются две переменные окружения:

- `LEPKA_MAIL_API_KEY` — секретный ключ Resend с правом отправки писем.
- `LEPKA_MAIL_FROM` — отправитель, разрешённый в Resend, например адрес на вашем подтверждённом домене.

Задайте их вне исходного кода: в настройках облачной среды или в окружении
процесса на своём компьютере. Не добавляйте ключ в Git. При работе Resend
в тестовом режиме получатели могут быть ограничены правилами сервиса.
`python main.py` не отправляет писем автоматически.

Следующее описание локального режима относится к запуску без адреса API. В серверном
режиме эти операции выполняются сервером по инструкции выше.

Новая регистрация создаёт неподтверждённый аккаунт и открывает ввод кода.
Код подтверждения регистрации действует 24 часа. Если письмо не отправилось,
используйте «Подтвердить регистрацию» на экране входа после настройки почты.
Не нужно регистрировать тот же аккаунт заново или удалять базу.
Код восстановления и смены email действует 10 минут. Код одноразовый,
после пяти ошибок нужен новый; повторная отправка возможна через минуту.
Коды не показываются в интерфейсе и не записываются в журналы.

После пяти ошибок вход блокируется на 15 минут; после трёх ошибок текущего
пароля его смена блокируется на 5 минут. Выход отзывает текущую сессию,
смена пароля/email и восстановление пароля отзывают все сессии аккаунта.
Сессия проверяется при следующем действии в другой открытой вкладке.
Пароли в пользовательской базе не заменяются при обновлении.
Старые аккаунты сохраняют доступ; миграция не доказывает владение их почтой.

При удалении аккаунта удаляются его личные записи SQLite. Публикации заменяются
заглушками, чтобы сохранить комментарии других пользователей. Для заглушек
используется заблокированная техническая запись автора. Старые записи-сироты
автоматически не удаляются. Перед обновлением сохраните копию существующей базы.

Подробности реализации, проверки и оставшиеся ограничения: `docs/day2_stabilization.md`.

## Проверка проектов

Дедлайн необязателен. Если он указан, требуется существующая календарная дата
строго в формате `ДД.ММ.ГГГГ`, например `25.04.2026`. Пробелы по краям
убираются, прошедшие даты допускаются. Пункт 4.1.19.4 в `docs/ТЗ` допускает этот формат и пустую дату.
Кнопка календаря открывает DatePicker из пункта 4.1.4.9; ручной ввод сохранён.

В «Проектах» проверьте следующие действия на специально созданном тестовом проекте:

1. Введите `НЕ ДАТА`, затем `31.04.2026`: сохранение должно отклоняться с сообщением.
2. Создайте проект с пустым дедлайном: в карточке появится «Без дедлайна».
3. Добавьте два этапа, прикрепите фото к одному и отметьте его: прогресс станет 50%. Новый этап без фото завершить нельзя.
4. Удалите незавершённый этап: прогресс станет 100%.
5. Войдите в другой аккаунт: этот проект не должен отображаться.
6. Вернитесь в первый аккаунт и удалите тестовый проект: вместе с ним удаляются оставшиеся этапы.

Команда автоматических проверок приведена выше. `tests/test_projects.py`
проверяет также подстановку чужих идентификаторов на уровне сервисов и SQL,
удаление всех этапов и откат транзакции при ошибке. `tests/test_startup.py`
проверяет обработчики формы проектов с настоящими элементами Flet и транспортом
в памяти. Каждый тест использует временную SQLite-базу; пользовательская база
не удаляется и не изменяется. Ранее возникшие записи-сироты автоматически
не удаляются: для очистки старых данных нужна отдельная проверка и резервная копия.

## Инструменты для лепки

После обновления повторите установку `-r requirements.txt`: для PNG нужен Pillow.

1. Во вкладке «Цвета» выберите 2–5 цветов. Доли автоматически приводятся к 100%; сумма граммов совпадает с весом, округлённым до 0,01 г. Пустой вес означает 100 г; некорректное число отклоняется.
2. Сохраните смесь, откройте её кнопкой «Открыть рецепт» в «Моих смесях», затем проверьте удаление тестового рецепта.
3. Нажмите «Экспорт PNG». В браузере файл передаётся для скачивания; в настольном режиме открывается выбор пути. Существующий файл не перезаписывается.
4. В «Поиске» проверьте категорию, сложность и время. Откройте урок, отметьте материалы и выполненный шаг. После возвращения в урок отметки и позиция сохраняются для вошедшего пользователя.
5. Добавьте урок как проект: этапы копируются вместе с ним. Задайте параметры генератора идей и добавьте идею в проекты — появится начальный список этапов.
6. В «Проектах» измените название, описание, дедлайн и текст этапа; прикрепите фото и проверьте прогресс после отметки этапов.

Каталог содержит шесть встроенных уроков со схематичными иллюстрациями. Видео пока нет: фильтр «Только с видео» выдаёт пустой результат.
Смеси, проекты и прогресс уроков сохраняются локально, в том числе при серверной авторизации.

Отчёт этапа, уточнение предыдущего аудита и подробные сценарии:
[docs/day3_tools.md](docs/day3_tools.md). На этом этапе прошли 112 автоматических проверок на временных базах.

## Публикации с фотографиями

На «Главной» можно добавить 1–10 фотографий JPG, PNG или WebP до 10 МБ каждая.
После загрузки заполните название, описание, категорию и теги, затем нажмите
«Опубликовать». Пока идёт загрузка, публикация недоступна. Ошибочный файл можно
добавить заново; незавершённую загрузку — отменить.

Фотографии уменьшаются до 1600 пикселей по большей стороне, переводятся в JPEG
и сохраняются в SQLite без EXIF/GPS. Исходные файлы не меняются. Изображения больше
20 мегапикселей и анимация отклоняются. Старые текстовые работы остаются в ленте.

Фильтр «Только мои работы» и кнопка «Мои работы» в профиле открывают свои публикации.
В карточке можно переключать фото, ставить/снимать лайк, оставлять комментарии.
Свои комментарии можно менять в течение 30 минут и удалять в любое время;
разрешено до пяти комментариев в минуту. Для удаления своей работы требуется
подтверждение: вместе с ней удаляются её фото, лайки и комментарии.

Без адреса API публикации видны пользователям текущей локальной базы.
При подключённом API лента общая для клиентов этого сервера. После обновления
перезапустите API и приложение, сохранив прежние каталоги данных.
Отчёт и сценарии: [docs/day4_community_android.md](docs/day4_community_android.md).
Текущий полный набор — **227 автоматических проверок**, все на временных данных.

## Проект → публикация → рецепт в палитре

В карточке личного проекта «Добавить смесь из палитры» выбирает сохранённый рецепт.
Сохраняется копия с цветами, процентами и граммами: удаление исходной смеси из
палитры не меняет проект.

Кнопка «Опубликовать в сообщество» открывает отдельную форму. Выберите итоговое
фото из этапов, отметьте шаги и смеси, которыми хотите поделиться. Укажите
описание для сообщества, сложность, время выполнения, материалы и инструменты
(по одному на строку). До 100 выбранных шагов и 10 фото; текстовые шаги без фото
тоже поддерживаются. Личные заметки и дедлайн не публикуются.

Работа появляется на «Главной», в «Моих работах» и в поиске. «Открыть мастер-класс»
открывает отдельный экран как у уроков: материалы и инструменты с чек-листом,
шаги в порядке проекта, фото каждого выбранного шага, «Предыдущий»/«Следующий»,
личный прогресс и «Добавить как проект». Для шага без фото показывается пояснение.
Прогресс сохраняется для каждого читателя отдельно. При добавлении в свои проекты
копируются описания шагов и смеси; этапы начинаются невыполненными, свои фото
можно прикрепить по мере работы.

Поиск учитывает название, описание, теги, автора, материалы и инструменты.
Фильтры сложности и времени действуют и на новые мастер-классы. Старые работы
без этих данных показываются при снятых ограничениях; «Только с видео» их скрывает.
Ранее созданные публикации проектов тоже открываются, но сложность, время и
материалы в них не выдумываются. Для заполнения этих полей опубликуйте проект
заново с новой формой.

Другой пользователь того же сервера (или той же базы в локальном режиме) может нажать «Сохранить рецепт в мою
палитру» на экране мастер-класса и открыть его на вкладке «Цвета». Рецепт копируется с пропорциями и
массой, а не только с HEX. Повторное нажатие не создаёт второй одинаковый рецепт.
Изменение или удаление личного проекта не меняет публикацию; удаление публикации
не удаляет уже сохранённый другим пользователем рецепт.

Серверное сообщество подключено: оба клиента должны использовать один API.
Пока сервер работает только локально, проверяйте его на компьютере. Для разных
устройств потребуется доступный им HTTPS-адрес; публичное размещение и Android
ещё не проверены. Прогресс мастер-класса сохраняется на сервере, сохранённый
рецепт и копия личного проекта — на устройстве читателя.

Прежние местные публикации не отправляются автоматически. В серверном режиме
откройте в профиле «Публикации на этом устройстве» и выберите свою работу для
отправки. Местная копия сохранится, повторная отправка не дублирует работу.
Кнопка показывает публикации текущей привязки серверного аккаунта; данные
отдельного старого локального аккаунта остаются доступны в локальном режиме.

## Аватар и фото этапов

В профиле «Выбрать аватар» загружает изображение, автоматически обрезает его
по центру до круга 512 × 512 и сразу сохраняет. Затем можно менять остальные
поля кнопкой «Сохранить профиль»: изображение сохранится. Поддерживаются JPG,
PNG и WebP до 10 МБ. Исходный файл на диске не меняется.

В локальном режиме аватар хранится в клиентской SQLite, в серверном — отправляется
API и хранится в базе аккаунтов. После обновления перезапустите **сервер API
и приложение**, используя прежние папки данных.

У каждого этапа проекта появились кнопки добавления, замены и удаления фото.
Фото проекта приватны и пока хранятся локально. Перед новой отметкой выполнения
нужно прикрепить фото; у завершённого этапа его можно заменить, а для удаления
сначала снять отметку. Старые отметки выполнения не сбрасываются при обновлении.

## Текущие ограничения

В коде есть формы регистрации, профиля, смешивания цветов, проектов, уроков и публикаций. Автотесты проверяют основные переходы, аккаунты, профили, настройки и проекты; полные испытания каждой функции на Android ещё предстоят.

Google-вход не подключён. Подтверждение регистрации, смена email и восстановление пароля используют письма Resend; без настройки почты эти операции не завершатся. «Запомнить меня» пока отключено: безопасное сохранение токена на устройстве не реализовано. Язык сохраняется в настройках, но полного английского перевода нет. Серверное сообщество работает при заданном API; очередь оффлайн-действий и синхронизация личных проектов/палитры ещё не реализованы. Экспорт смеси реализован в PNG; PDF не добавлен. Урокам нужны пошаговые фотографии/видео, проектам — изменение порядка этапов, JSON-экспорт/импорт и напоминания. Полноценный 3D, AR и push требуют отдельной работы. Эти требования остаются открытыми; исходное ТЗ не изменяется.

## APK

Для сборки подготовьте отдельную новую папку вне репозитория. Скрипт копирует
только перечисленные модули и ресурсы клиента, создаёт отдельную мобильную точку
входа и `requirements.txt`. Базы, `.env`, виртуальное окружение и `backend/`
не копируются. Переменные окружения в пакет не записываются.

```powershell
.\.venv\Scripts\python.exe -m pip install "flet-cli==0.28.3"
.\.venv\Scripts\python.exe scripts\prepare_android.py --output ..\lepka-android --api-url https://api.example.com
Remove-Item Env:LEPKA_MAIL_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:LEPKA_MAIL_FROM -ErrorAction SilentlyContinue
.\.venv\Scripts\flet.exe build apk ..\lepka-android --arch arm64-v8a
```

Замените пример настоящим публичным HTTPS-адресом своего сервера аккаунтов.
Если `--api-url` не указан, берётся адрес из `assets/client_config.json`. При пустом
адресе Android покажет сообщение о необходимости настройки API. Настройка сервера
описана в `backend/README.md`; ключ Resend остаётся в процессе сервера.

Flet может загружать Flutter, JDK и Android SDK, это требует времени и места.
